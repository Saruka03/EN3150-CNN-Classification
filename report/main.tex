% -------------------- 1. INTRODUCTION --------------------
\section{Introduction}
Convolutional neural networks (CNNs) are widely used for image classification, but the memory and computational requirements of large models can make deployment difficult on embedded devices and edge nodes. This assignment investigates the trade-off between classification performance and resource efficiency by developing two custom CNNs and comparing them with two pretrained lightweight architectures.

Fashion-MNIST is used as the image-classification dataset. Model A uses conventional two-dimensional convolutions, while Model B uses depthwise separable convolutions and is constrained to no more than 100,000 trainable parameters. MobileNetV2 and EfficientNetB0 are fine-tuned as pretrained reference models.

The objectives are to prepare low-resolution data with a 70/15/15 split; design and document two custom CNN architectures; compare Adam, SGD and SGD with Momentum for Model B; evaluate all models using classification metrics and resource measures; and discuss accuracy, memory footprint and computational cost.

\section{Custom CNN Architecture Design}
\subsection{Model A: Standard CNN}
Model A is the baseline CNN. Conventional convolutional layers extract spatial features, and max-pooling layers reduce feature-map dimensions. The resulting representation is flattened and passed to a dense hidden layer and a ten-class softmax output.

For a conventional convolution with biases, the parameter count is
\begin{equation}\label{eq:convparams}
P_{\mathrm{conv}}=(K_hK_wC_{\mathrm{in}}+1)C_{\mathrm{out}},
\end{equation}
where $K_h$ and $K_w$ are kernel dimensions, $C_{\mathrm{in}}$ is the number of input channels and $C_{\mathrm{out}}$ is the number of filters. For a dense layer,
\begin{equation}\label{eq:denseparams}
P_{\mathrm{dense}}=(n_{\mathrm{in}}+1)n_{\mathrm{out}}.
\end{equation}

\subsection{Model B: Lightweight CNN}
Model B replaces conventional convolutions with depthwise separable convolutions. A depthwise convolution applies a spatial filter independently to each input channel; a pointwise $1\times1$ convolution combines the channel-wise features. This factorization can reduce parameter count and multiply-accumulate operations relative to a conventional convolution with comparable channel dimensions.

For a depthwise separable convolution with a $K_h\times K_w$ kernel, $C_{\mathrm{in}}$ input channels and $C_{\mathrm{out}}$ output channels, with one bias per output channel,
\begin{equation}\label{eq:sepparams}
P_{\mathrm{sep}}=K_hK_wC_{\mathrm{in}}+C_{\mathrm{in}}C_{\mathrm{out}}+C_{\mathrm{out}}.
\end{equation}

\subsection{Activation functions and hardware considerations}
ReLU is used in hidden layers because $f(x)=\max(0,x)$ is computationally simple and avoids the exponential calculations used by sigmoid and tanh. It is widely supported by deep-learning runtimes. The output layer uses softmax to convert class logits into a probability distribution over ten classes. Softmax requires exponentials but is appropriate for normalized multi-class probabilities; its cost should be considered separately from the main convolutional computation.

\subsection{Accuracy, memory and computation trade-offs}

\begin{enumerate}[leftmargin=1.5em]

    \item \textbf{Highest test accuracy:}

    \item \textbf{Model size:}
    Model B has only $4{,}738$ parameters, compared with

    EfficientNetB0. This makes Model B much more compact.

    ImageNet pretraining did not improve accuracy over Model A.
    MobileNetV2 achieved $88.23\%$, while EfficientNetB0 achieved
    $89.29\%$. However, EfficientNetB0 performed slightly better
    than Model B.

    \item \textbf{Training time:}
    The model with the shortest measured training time per epoch
    should be identified from the experimental results. Training
    time alone does not determine inference speed or energy use,
    which depend on the hardware and implementation.

    \item \textbf{Model A versus Model B:}
    Model B achieved nearly the same accuracy as Model A while
    reducing the parameter count by approximately $92.22\%$.
    This makes it a useful option when memory is limited, with
    only a small reduction in test accuracy.

    \item \textbf{Overall comparison:}
    Model B offers a compact and efficient architecture, while
    Model A provides the highest test accuracy. Pretrained models
    have substantially more parameters but can benefit from
    previously learned features. The best choice depends on the
    application's accuracy and resource requirements.

\end{enumerate}

% -------------------- 7. LIMITATIONS --------------------
\newpage
\section{Limitations}
Fashion-MNIST is a low-resolution dataset with ten classes, so results may not generalize to more complex real-world imagery. The pretrained networks receive resized three-channel inputs, whereas custom CNNs can operate directly on grayscale images; this difference should be considered when interpreting computation and input-processing overhead.

Training time depends on CPU/GPU hardware, runtime configuration, batch size, software versions and whether data loading is included. Saved model size depends on serialization format. Parameter count, file size and training time do not alone measure on-device inference latency, peak RAM use, energy consumption or multiply-accumulate operations.

% -------------------- 8. CONCLUSION --------------------
\section{Conclusion}

This assignment compared two custom CNN architectures with two pretrained image-classification networks on Fashion-MNIST. Model A provided a conventional CNN baseline, while Model B used depthwise separable convolutions to reduce the parameter count.

Model A achieved the highest test accuracy of 89.58\%, followed by EfficientNetB0 at 89.29\%, Model B at 89.10\%, and MobileNetV2 at 88.23\%. With only 4,738 parameters, Model B achieved competitive accuracy while using far fewer parameters than the pretrained models. Overall, the results show that a carefully designed lightweight CNN can achieve comparable performance with much lower model complexity, making it a practical choice when memory and computational resources are limited.
